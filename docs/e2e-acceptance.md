# 끝에서 끝 받아들임 체크리스트 (사람이 하는 단계)

spec #93 「받아들임」, 티켓 #101. **운영에서 코딩 문제 1개를 Windows 앱으로 응시**해 편집·AI diff 수락·로컬 실행·제출 → 히든 채점 → AI 활용 평가 → 대시보드 결과까지 한 줄기로 확인한다. 스모크(`e2e/smoke.ps1`, 기계 주체)가 못 보는 것 — 앱 화면·웹캠·AI 도우미·대시보드 화면 — 을 사람 눈으로 보는 단계다. 운영 데이터는 이 절차를 하는 사람이 만든다(자동화·작업자는 만들지 않는다).

## 준비물

| 무엇 | 비고 |
|---|---|
| Windows 11 PC 한 대(대화형 로그인 세션) | **RAM 16GB 이상**, 웹캠, (있으면) GPU — **사람이 로그인한 데스크톱**에서 한다 |
| Docker Desktop(Linux 컨테이너 모드) 설치·실행 | 라이선스 안내: 개인 사용은 무료, 일정 규모 이상 기업의 업무용 사용은 유료 |
| 설치 파일 `promptlab-app-setup-<버전>.exe` | Actions `.github/workflows/windows-build.yml`의 artifact. 서명 인증서가 없으면 SmartScreen 경고가 뜬다(「추가 정보 → 실행」) |
| 대표(또는 출제자) 계정으로 대시보드 로그인 | https://promptlab.sandcorp.co.kr — 시범 조직이 **승인**된 상태여야 시험을 만들 수 있다(운영자 화면 「시범 조직 승인」) |
| 응시자용 이메일·카카오 계정 | 초대 메일을 받을 수 있는 주소(본인 다른 주소 가능) |
| 대화 평가 키 | 서버 env `PROMPTLAB_ANTHROPIC_API_KEY`가 있어야 AI 활용 평가·리포트가 켜진다(없으면 아래 8번에서 「평가 없음」이 정상) |
| 네트워크 | AI 모델(4.7GB)·러너 이미지(~350MB 압축)를 내려받을 수 있는 연결, 설치 전 여유 디스크 15GB |

## 순서와 기대 결과

### A. 출제 (대시보드, 대표·출제자)

1. 조직 화면에서 **시험 만들기** — 용도 「채용」(결과가 응시자에게 안 보임) 또는 「사내 진단」(결과 공개를 켜면 점수 보임) 중 하나, 문제은행(내장 시험 문항 8개 중 하나)에서 **문항 1개**, 허용 언어는 기본 4개 전부. 
   - 기대: 시험이 목록에 생긴다. 시험 설정 탭에 허용 언어·점수 비율 w(AI 활용 비중)·추가 기준표가 보인다.
2. 응시자 이메일로 **초대**(서랍).
   - 기대: 초대 메일(SMTP 설정이 켜져 있을 때) 또는 초대 링크, 초대 현황에 「초대함」.

### B. 설치·점검 (Windows 앱)

3. 설치 파일 실행 → **「최소 사양」 안내 페이지**(RAM 16GB·Docker Desktop·라이선스 문장)가 뜨고, 설치 중 **모델 내려받기 진행 막대**가 보인다(끊기면 3번 다시 시도).
   - 기대: 설치 끝, 바탕화면·시작 메뉴에 「PromptLab」. 모델은 `%LOCALAPPDATA%\promptlab\models`.
4. 초대 링크를 브라우저에서 열고 카카오 로그인 → 앱을 열어 **「내 시험 불러오기」**.
   - 기대: 내 시험 목록에 방금 만든 시험이 보인다.
5. **응시 전 점검·동의** 화면.
   - 기대: 웹캠(얼굴 하나 인식) · 장치 카드에 **AI 속도 GPU 또는 CPU**, **메모리**(16GB 미만이면 경고만) · **Docker**(이미지 받기 진행 → 「준비됨」). 안내문 동의 + 기준 사진 올리기 → 「응시 시작」이 열린다. Docker가 없으면 「응시 시작」이 안 열리고 설치 안내 링크·라이선스 문장이 보여야 한다.

### C. 응시 (Windows 앱, 풀스크린 잠금)

6. 문항 시작 → 응시 화면(1440 이상이면 3칸: 문제 | 편집기 | AI 도우미).
   - 기대: 문제 설명·예제·언어별 틀, 머리에 문항 탭·잠금·웹캠·남은 시간. 언어를 바꾸면 그 언어의 틀로 초안이 바뀌고 이전 언어 초안은 보존된다.
7. 코드를 **편집**한다(일부러 틀리게 한 뒤 고쳐도 좋다). 그다음:
   - **예제 테스트**(Ctrl+Enter)·**실행**(Ctrl+Shift+Enter, 입력 한 번) — 기대: 로컬 Docker로 돌고 결과 표(통과/실패·반환값·시간).
   - **AI 도우미**에게 「이 코드를 개선해 줘」처럼 요청 — 모델을 처음 올릴 때 수십 초 걸린다(그동안 코드는 쓸 수 있다). 기대: 도구 호출 후 **편집 제안 diff 덮개**가 편집기에 뜬다 → **수락**하면 그 범위만 바뀌고 **Ctrl+Z 한 번으로 되돌아간다**. 거절도 한 번 해 본다(다음 메시지에 결정이 전달된다).
   - 시험 중 **붙여넣기**: 앱 밖에서 복사한 글을 붙여넣으면 막히고 알림이 뜬다(앱 안 복사·붙여넣기는 된다).
   - Alt+Tab으로 잠깐 나갔다 온다 — 포커스 이탈이 기록된다(의심 신호 6번에서 확인).
8. **제출** — 대화 상자(언어·바이트·마지막 예제 테스트) 확인 → 제출.
   - 기대(채용): 「응시 완료」만 보인다. (사내 진단+결과 공개: 채점 대기 → 통과 수·최종 점수와 계산식.) 로그는 5초마다 올라가고 제출 직전에 한 번 더 올라간다.

### D. 결과 (대시보드, 결과 보기 역할 — 관리자·감독관·열람자)

9. 시험 상세 **응시 결과**: 응시자 줄에 상태가 「채점 중 → 완료」, **최종 점수·통과율·AI 활용·언어·소요 시간**.
   - 기대: 통과율 = 히든 테스트 통과 수/전체(모범 답안 수준이면 100%). **AI 활용** 평균은 평가가 끝난 뒤에 채워진다(보통 수 분, 큐 조직당 2). 평가 키가 없으면 AI 활용이 비고 최종 = 통과율(「통과율만」).
10. 줄을 눌러 **응시자 상세** 열기:
    - **점수 탭**: 제출 코드(읽기 전용·언어), **편집 타임라인**(코드 스냅숏 줄 diff, AI 제안의 수락/거절·「수락 뒤 수정」), **AI 대화 원문**(턴 번호), 로컬 실행 기록. 오른쪽 칸의 문항 점수·계산식·평가 항목(지시 품질·검증·AI 제안 비판·효율)과 **근거 칩 「턴 n」·「제안 #k」** — 누르면 왼쪽 해당 턴/제안으로 스크롤되고 강조된다.
    - **과정 다시보기**: 문항 시작·언어 고름·스냅숏·AI 메시지·제안 수락·로컬 실행·붙여넣기 막음이 시간순으로, 체인 검증 신호 없음.
    - **의심 신호**: 6번에서 한 포커스 이탈·붙여넣기 막음이 뜬다(판단은 고객사).
    - **웹캠 사진**: 기준 사진·스냅샷(감독 권한).
    - **AI 리포트**: 키가 있으면 강점·약점·개선 제안(점수를 바꾸지 않는다는 면책 문구).
11. (선택) 결과 CSV 내려받기 — UTF-8 BOM, 제출 코드·히든은 없다.

### E. 정리

12. 앱 제거(설정 → 앱 → PromptLab, 또는 `unins000.exe`). 모델 캐시는 남는다.
13. 조직 관리자가 응시자 상세의 **「데이터 삭제」**(이메일 확인 입력)로 이 응시 데이터를 지운다(#55) — 감사 로그에 한 줄이 남는다.

## 합격 기준

- 3~8번이 막힘 없이 끝나고, 9번의 통과율이 기대와 맞고, 10번의 점수 탭에서 근거 칩이 해당 턴·제안으로 이동한다.
- 막힌 단계가 있으면 **단계 번호·화면 문구·(가능하면) 스크린샷**을 티켓 #101에 남긴다. 앱 로그는 `%LOCALAPPDATA%\promptlab`(과정 로그 `logs\`)에 있다.

## 미리 알아 둘 것

- CI는 Windows 앱 빌드만 수행한다. `e2e/smoke.ps1`은 운영 제출을 포함하므로 자동 CI에 연결하지 않는다; 이 체크리스트가 화면·웹캠·AI 도우미 인수 범위를 다룬다.
- Windows 빌드와 모델 다운로드 설명은 `docs/windows-host.md`를 본다.

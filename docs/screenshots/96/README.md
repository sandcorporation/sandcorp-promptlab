# #96 문제 편집·시험 설정 화면 스크린샷

작업 트리(브랜치 t96)로 서버 이미지(`docker/server.Dockerfile`, wasm 대시보드 포함, 태그 `promptlab-t96-shot`)를 빌드하고 Postgres 17 컨테이너와 같은 전용 도커 네트워크에 띄웠다. 시드는 SQL 직접: 사용자 `m_`+ULID 꼴 1명(admin), 승인된 조직 1개, 세션 쿠키 `pl_session`의 sha256을 `sessions`에 직접. 조직 문제 2개(「두 수 더하기」 = 발행·점검 결과 있음, 「배열 최댓값 (초안)」 = 점검 없음), 점검 한 줄(6/6 통과·`compiled: true`, 언어별 틀 컴파일은 C++만 실패 → 「발행 불가」, source = 문제 원본 스냅숏이라 current), 시험 1개(사내 진단, 허용 언어 python·javascript). 운영 auth 없음. Playwright(헤드리스 크롬)로 폭 1440(높이 900)·390(높이 844) × `colorScheme` 라이트·다크, `fullPage`, JPEG 품질 55 — 화면마다 4장, 총 8장.

| 화면 | 주소 | 보이는 것 |
|---|---|---|
| `problem-editor` | `#/orgs/<org>/problems` → 「두 수 더하기」 「열기」 | 문제 편집 전체 페이지: 기본 정보·함수 서명 편집기·테스트 케이스·모범 답안·언어별 틀 미리보기(Java 21 선택)·발행 전 점검 패널(데스크톱은 오른쪽 칸, 모바일은 맨 아래 — 「발행 불가」, 모범 답안 6/6, 언어별 컴파일 통과·C++17 실패 + 안내) |
| `exam-settings` | `#/orgs/<org>/exams/<exam>/items` (「문항과 채점」 탭) | 문항 표, 「허용 언어」(Python·JavaScript만 체크), 점수 비율, 대화 평가 기준표, 결과 공개, 보관 기간 |

파일명은 `<화면>-<desktop|mobile>-<light|dark>.jpg`(8장).

## 390 가로 넘침 측정

8장 모두 `documentElement.scrollWidth == clientWidth`(데스크톱 1440/1440, 모바일 390/390). `.sc-table-scroll`·`table`·`.sc-table`·`.sc-panel`·`.sc-split`(안쪽 `textarea`·`pre` 제외)의 `scrollWidth > clientWidth`인 요소 0개. **390에서 문서 넘침 0.**

## 눈에 띈 결함(고치지 않음)

1. 촬영 방식 탓(결함 아님): 캡처 스크립트가 페이지의 `select` 두 개(모범 답안 언어·틀 미리보기 언어)를 모두 Java로 바꿨다. 그래서 모범 답안 언어는 Java 21인데 코드는 Python 그대로다.
2. `exam-settings`: 문항 표의 「문제」 칸이 제목이 아니라 문제 id(`org-shot1`)로 나온다.
3. `exam-settings`: 대화형 시절의 「점수 비율」(숨은 케이스 50% / 대화 평가 50%) 슬라이더, 「대화 평가 기준표」(Claude 채점·추가 항목 2개), 머리의 「점수 비율 50 : 50」이 그대로 남아 있다. 지금 최종 점수는 통과율뿐이고 대화 평가는 #99가 다시 짓는다 — 코딩 문제에서는 혼란스럽다(#96 범위 밖일 수 있음).
4. `problem-editor`(데스크톱): 점검 패널의 「발행 불가」 막대가 옅은 분홍 바탕에 글자가 작고 흐려 라이트에서 잘 안 읽힌다(다크 모바일은 읽힘). 같은 패널의 「저장하지 않은 변경이 있습니다」 문구는 저장 전이라 뜬 것으로 보이나 새로 연 직후에도 「저장 안 됨」 배지가 머리에 뜬다 — 처음 열었을 때 이미 저장 안 됨 상태인지 확인 필요.
5. `problem-editor`: 예제·히든 케이스 JSON 칸이 pretty-print 탓에 세로로 길어(케이스 하나가 8줄) 칸 안에서 많이 스크롤해야 한다. 한 줄에 `{"args":[1,2],"expected":3}` 꼴이면 더 많이 보인다.
6. `problem-editor`·`exam-settings` 데스크톱: 전체 페이지 캡처에서 왼쪽 사이드바 배경이 뷰포트 높이(900)에서 끊긴다 — 캡처 방식(`fullPage`, sticky 사이드바) 탓으로 보이며 실제 사용에서는 문제 없을 듯.
7. `exam-settings` 모바일: 이동 경로가 「샌드 … › 시… › 신입 진단…」으로 심하게 잘려 어느 화면인지 읽기 어렵다. 탭이 5개 중 4개만 보이고 「실시간 감독」은 가로로 잘려 있다(탭 줄 자체 스크롤로 보이나 단서 없음).
8. `problem-editor` 모바일: 점검 패널이 페이지 맨 아래로 내려가 「발행」 단추를 누른 뒤 결과를 보려면 끝까지 스크롤해야 한다.
